# 2026-08-31 — read-path-switch + current-utr-source

上一个 change 把队员注册表建好并迁进了线上两季，但**没有一条读取路径读它**。管理界面
因此是个写进黑洞的表单：改一个名字、裁决一个冲突，名单页和排阵页什么都不变。这次把
那个窗口关上。

## 完成内容

十二个 commit（`c7925f2..783b94e`），六个受评组的分数：96 / 99 / 98 / 100 / 100 / 100
（阈值前四组 80，含 VISUAL DIFF 的两组 70）。

- **三处读取换源**：球队列（人数改数成员关系、性别取自队员记录）、球队名单、排阵引擎。
- **参赛 UTR 推导链**（`app/players/utr_chain.py`，纯函数）：本赛季冻结值 → 当前
  `rated` 双打值 → 最近一个有值赛季的 match UTR（不限上一年）→ 都取不到则不参与排阵。
  这是组委会自己的算法，所以名单页与引擎**共用同一条**，配了跨模块一致性断言。
- **估算标三处**：队员的数字旁、整套候选上、可达上限旁。合法性是整套的属性，一个估算
  值就让「这套合法」本身成为估算。
- **BREAKING**：锁定 key 从 `roster_entries.id` 换成 `p<player_id>`，旧分享链接**解析
  失败**并明说是旧格式。两套 id 都是小整数且互不相干，不换格式的话旧链接会静默锁到两个
  不相干的人，而算出来的阵容看起来完全正常。
- **导入器自锁**：默认拒绝，`--i-know-it-is-not-read` 绕过且仍打印同一句说明。

## 两次 BLOCK，第二次是真 bug

1. **group 1**：`origin` 用了裸 `str` 而 contract 写的是枚举；`prior_season` 分支的
   未裁决标志没测试。
2. **group 2**：`get_team_roster` 把「一个数都取不到」的队员 `continue` 掉了 ——
   代码里的注释正好写着「丢掉会误报阵容」。后果不是少一行，而是**两个端点互相矛盾**：
   球队列把他算进 `player_count`，名单不返回他，页面上没有任何迹象说少了人。
   根因是换数据源放宽了 `match_utr` 的 NOT NULL 不变式，而响应模型没跟着放宽 ——
   这条进了 design（新增 D5b）、spec、mocks 与 pitfalls。

评审没抓到、我自己在实跑时抓到的一处：`_player_out` 里 provenance 查不到时兜底成
`frozen`，等于给一个来源不明的数字盖「组委会冻结」的章。改成索引取值、缺失即 KeyError；
破坏验证从 0 条红变 14 条红。

## 三处范围由项目负责人拍板

  原本指着一列并不存在的东西 —— explore 阶段的事实错误，propose 时照抄没核。
- **`--color-warning` 从 `#b8860b` 调深到 `#8a6508`**。实测 `估算` 与既有的 `待定`

  16px padding，三个 `<CardHeader className="mb-0">` 保留着 12px 下边距。用新旧两版各量

  效果 —— 之前 16px padding 让表头分隔线两端悬空）。

# current-utr-source

同一天的第二个 change。上一个把读取路径切到了注册表，于是名单页多出「当前单打 / 当前
双打」两列 —— 而那两列**一整列是 `—`**：五个字段从来没有入口。推导链第二步（当前
`rated` 双打值）因此永远不命中。

## 完成内容

十七个 commit（`4cbe2f9..4ae8b13`），六个受评组：**100 / 97 / 95 / 98 / 99 / 98**
（阈值前三组 80，含 VISUAL DIFF 的三组 70）。

- **往返表**：系统按队导出一张已带 `players.id` 与姓名的表 → 人在 Sheets 里填 → 整块
  贴回或传 CSV → 先看差异 → 确认才写。
- **绝不猜「这一行是谁」**。id 原样往返，姓名只作校验位，`id` 缺失时 **MUST NOT** 回退
  到姓名（单独一条 scenario 钉住）。负责人指出 profile ID 会变、姓名会重，两者都不能
  当依据 —— 而自增 id 两者都不受影响。
- **「空」三种含义**：空白 = 不改、`-` = 清空、值与状态必须成对。
- 差异屏按人分组 + 顶部按字段的改动计数（补回列不对齐丢掉的「整列粘错」信号）；
  有任何一行被拒 → 整批不写。
- 名单页行内改一个人；跨组的队员在差异屏被点名。

## 交付后追加的一条：参赛 UTR 镜像

上线后负责人提出：赛季没锁时，填当前双打 UTR 应当**同时**把该赛季的参赛 UTR 设成同一个
值。这**推翻了本 change 原本明写的一条 Non-Goal**（「不动参赛 UTR」），所以改的是
proposal、design（新增 D9）与 spec（新增一条 requirement 加 5 个 scenario），而不是
偷偷加代码。

覆盖是无条件的，包括组委会的值。理由是流程上的：组委会数据一导入就立刻锁季，两者不重叠。
**锁是唯一的护栏**，代价写进了 design —— 忘了锁，一次手填就会无声覆盖冻结值。

同批还改了：状态默认 `rated`（只填数字那个框）、两列加宽（实测内容 166px 而列宽 112px，
第一次只加到 150px **还是切**，量出来才改到 184px）。

## 两次 BLOCK

1. **group 1**：小数按字符串比 —— `Decimal("7.00")` 与手填的 `7` 被判成一处改动，
   「原样往返 0 处改动」那条地基当场塌掉；`-` 能只清一半留下「有状态没有值」；同一个
   id 出现两次静默后者覆盖；CSV 引号转义缺失（名字带逗号会整行错位）。
2. **group 4**：评审在正文里列了 3 个 HIGH **却照样打分返回 PASS** —— 按协议 HIGH 应当
   直接 BLOCK。没有接受那个 PASS，逐条修了：响应模型进 OpenAPI、`UtrPanel` 补 8 条测试
   （两条验过红）、剪贴板失败会说出来。

## 自己抓到、评审没抓到的

- 差异屏 **28 个叶子节点低于 4.5:1**。根因是面板没给自己白底：`--color-muted` 在白底
  4.69、在页面底色 4.27，差 0.42 正好卡在阈值两侧。修后 0 个。
- 一条只在全套负载下红的测试。**第一次诊断错了** —— 把 `waitFor` 从 1s 调到 5s，那只是
  把「断言超时」换成「整条测试超时」，因为 `waitFor` 本来就会轮询到断言成立。真正的修法
  是等一个渲染出来的结果（回到导出页签），连跑三次确认。
