# 2026-08-31 — read-path-switch

上一个 change 把队员注册表建好并迁进了线上两季，但**没有一条读取路径读它**。管理界面
因此是个写进黑洞的表单：改一个名字、裁决一个冲突，名单页和排阵页什么都不变。这次把
那个窗口关上。

## 完成内容

十二个 commit（`c7925f2..783b94e`），六个受评组的分数：96 / 99 / 98 / 100 / 100 / 100
（阈值前四组 80，含 VISUAL DIFF 的两组 70）。

- **三处读取换源**：球队列（人数改数成员关系、性别取自队员记录）、球队名单、排阵引擎。
- **参赛 UTR 推导链**（`app/players/utr_chain.py`，纯函数）：本赛季冻结值 → 当前
  `rated` 双打值 → 最近一个有值赛季的 match UTR（不限上一年）→ 都取不到则不参与排阵。
  这是组委会自己的算法，所以名单页与引擎**共用同一条**，配了跨模块一致性断言。
- **估算标三处**：队员的数字旁、整套候选上、可达上限旁。合法性是整套的属性，一个估算
  值就让「这套合法」本身成为估算。
- **BREAKING**：锁定 key 从 `roster_entries.id` 换成 `p<player_id>`，旧分享链接**解析
  失败**并明说是旧格式。两套 id 都是小整数且互不相干，不换格式的话旧链接会静默锁到两个
  不相干的人，而算出来的阵容看起来完全正常。
- **导入器自锁**：默认拒绝，`--i-know-it-is-not-read` 绕过且仍打印同一句说明。

## 两次 BLOCK，第二次是真 bug

1. **group 1**：`origin` 用了裸 `str` 而 contract 写的是枚举；`prior_season` 分支的
   未裁决标志没测试。
2. **group 2**：`get_team_roster` 把「一个数都取不到」的队员 `continue` 掉了 ——
   代码里的注释正好写着「丢掉会误报阵容」。后果不是少一行，而是**两个端点互相矛盾**：
   球队列把他算进 `player_count`，名单不返回他，页面上没有任何迹象说少了人。
   根因是换数据源放宽了 `match_utr` 的 NOT NULL 不变式，而响应模型没跟着放宽 ——
   这条进了 design（新增 D5b）、spec、mocks 与 pitfalls。

评审没抓到、我自己在实跑时抓到的一处：`_player_out` 里 provenance 查不到时兜底成
`frozen`，等于给一个来源不明的数字盖「组委会冻结」的章。改成索引取值、缺失即 KeyError；
破坏验证从 0 条红变 14 条红。

## 三处范围由项目负责人拍板

- **名单页补当前单/双打 UTR 两列**。requirements 里那句「否则一整列『—』读起来像坏了」
  原本指着一列并不存在的东西 —— explore 阶段的事实错误，propose 时照抄没核。
- **`--color-warning` 从 `#b8860b` 调深到 `#8a6508`**。实测 `估算` 与既有的 `待定`
  只有 **2.99:1**，11px 小字要 4.5:1。改后名单页全部标记 4.69–15.31。顺带发现
  player 页早就把 `#8a6508` 硬编码了一遍 —— 同一个问题被就地绕过，现在收回 token。
- **`lib/cn.ts` 换成 `tailwind-merge`**。它原本是纯 `join`，两个同权重的类靠样式表顺序
  决胜负。审计发现两处覆盖**一直是静默失效的**：`<Card className="p-0">` 实际渲染
  16px padding，三个 `<CardHeader className="mb-0">` 保留着 12px 下边距。用新旧两版各量
  一遍 computed style 确认，这是本次唯一的额外渲染变化（在规则页，且是作者本来想要的
  效果 —— 之前 16px padding 让表头分隔线两端悬空）。

## 本机踩到的坑

同一个 TRUNCATE 陷阱吃了两次：补种 → 迁移 → 造演示数据 → 跑一次全套测试，本地库就又
空了，页面变 404，而正准备做视觉核对。顺序固定为**先跑测试，再补种，再核对**。

另一次误判来自 uvicorn 没带 `--reload`：改完后端刷页面看到的仍是旧字段形状，据此两次
下错结论（以为 `singles_utr` 没传出来、以为逐人 `origin` 是 null）。判断依据要用 `curl`
打接口，别只看页面。

## 部署顺序

后端先上、前端后上。新字段对旧前端是增补；反过来前端读到 `undefined`，
`origin !== "frozen"` 对每个人都成立，十个数字会全被标成「估算」。
