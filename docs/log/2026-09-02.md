### 做了什么

命名的过滤预设（preset）：把一支队当前的锁定 + 排除存成有名字的集合，列在排阵页、一键载入、
admin 可存/删。**载入 = 把锁定/排除写回 URL 参数**，搜索路径一个字没改——preset 只是同一批
query 参数的存储来源。

- 新 capability `lineup-filter-presets`：`zijing_cup.lineup_filter_presets` 单表（JSONB
  constraints、`unique(team_id,name)`、FK cascade、时间戳 server_default），存/列/删命令
  （同名 UPDATE 覆盖、空名/长度/每队≤50 守卫），GET(开放)/POST/DELETE(admin) 路由，写路由
  靠 `WRITE_METHODS` 中间件自动受保护。
- `lineup-ui` delta：控件里「已存阵型」块（桌面 + 抽屉），非 admin 只见列表+载入。
- **失效分锁定/排除**：锁定引用离队球员 → warning 拒载面板（点名线+编号+重建/删除，不猜替补、
  不渲染候选）；排除引用离队 → 照常载入（那条排除已无意义，静默丢）。检查用页面已有
  `search.roster` 前端比对，零额外请求。

### 应用期踩的坑

1. **Windows 大小写不敏感 FS 撞名。** `Presets.tsx`（组件）与 `presets.ts`（helper）同目录，
   `import { Presets } from "./Presets"` 解析到了 `presets.ts` → React 报「Element type is
   invalid ... got undefined」，tsc 反倒不报（它大小写敏感）。helper 改名 `presetLoad.ts` 解决。
2. **`.env` CRLF 让 curl header 带 `\r`。** 手工 POST preset 时 `X-Admin-Secret` 值带尾随
   `\r` → uvicorn 报 400「Invalid HTTP request received」。`tr -d '\r\n'` 掉。另外
   `grep ADMIN_SECRET` 会误匹配注释行，要 `grep '^ADMIN_SECRET'`。
3. **只读增强取数失败要降级。** 远程 migration 手工执行，新表在部署后、手工跑前不存在。
   `getTeamPresets` 原来 throw → 排阵页整页错误态。改成任何失败 `return []`：表没建就是
   「没有 preset」，排阵照常。已沉进 CLAUDE.md pitfalls。

## 发现：单座位 pin 不支持（下一个 change）

用户报 2026 银 ZJU-USC「每线只指定一个人、系统算不出合适阵容」。查明**不是计算 bug，是功能缺口**：
当前「锁定」是**整对**（一条线两个座位），半填的线被 `constraintsFromQuery` 无声丢弃（`if (first
&& second)`），后端 `_parse_locks` 也要求两个 key，引擎 locks 是 `dict[str, Pair]`。所以「钉一个人
到某条线、引擎配搭档」这个意图现在无法表达，半填还没有任何提示。下一个 change `lineup-single-pin`
去做：单座位 pin + 半填提示护栏。
