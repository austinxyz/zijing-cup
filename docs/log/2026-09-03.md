## lineup-single-pin（单座位 pin：钉一人到线、引擎配搭档）

opsx 四阶段走完并归档（`2026-09-03-lineup-single-pin`）。commit `6be71d1`(req) →
`64a3a6a`(propose) → `c4a9b64`(后端) → `cbd60a3`(前端) → `e5e0292`(验证) push master，
自动部署 Vercel + Render。无 migration。

### 起因

用户报 2026 银组 ZJU-USC「每条线只指定一个人、系统算不出合适阵容，实际上有」。系统调试
（systematic-debugging）查明**不是计算 bug，是功能缺口**：当前「锁定」是整对（一条线两个
座位），半填的线被 `constraintsFromQuery` 无声丢弃（`if (first && second)`），后端
`_parse_locks` 也要求两个 key。所以「钉一人、引擎配搭档」这个意图根本无法表达，引擎忽略
半填、给出没照钉法的阵容。→ 开这个 change 补齐。

### 做了什么

- 后端 `search_lineups` 收 `pins`（line→被钉者）：被钉线 `options[L]` = 含被钉者的合法对
  （把被钉者临时并回池子跑 `legal_pairs` 再筛），被钉者从其它线的 `available` 剔除、搭档
  现选、递归 used 集兜底；strongest/scarcest 排序不变。硬锁整对不变，pin/硬锁/排除可组合，
  女将可钉男双。
- `diagnose_line` 加 `pinned`：pin 那条线无解时只在含被钉者的对里跑四关分类、message 点名
  （`你把 X 钉在 L…`），不报无关的整池「本可行」原因。
- 冲突输入（同一人钉两线 / pin∩排除 / pin∩硬锁成员 / 一线两座同人）在 `search_team_lineups`
  抛 422。端点 `pin=LINE:key`（不重载 `lock=`）。
- 前端 `constraintsFromQuery` 分三态（一座位=pin / 两座位=硬锁 / 同人=无约束）；`lib/api`
  编码 pin；控件「已钉」badge + 「搭档交给引擎」小字（硬锁「锁整对」）；pin 无解走既有
  `NoSolution`（后端 message 已点名）。

### 应用期踩的坑

1. **`Candidate.name` 是 `last\tfirst` 制表符拼的**——pin 诊断 message 直接用 `pinned.name`
   在页面上显示成 `Hu\tMitch`。这是第二次栽（上次 infeasibility-detail 归因）。加了
   `_display_name` helper 格式化。已沉进 CLAUDE.md pitfalls。
2. **`reseed-local.sh` 用 `uv run python`，本机已被 Application Control 拦**（`os error 4551`）。
   改成手动用 `backend/.venv-std/Scripts/python.exe -m app.seeds.load_rules`（rosters/team_names/
   players.migrate 同）按序补种。已沉进 CLAUDE.md pitfalls。
3. **女将会救男双线的 pin 无解场景**——构造 pin-over-cap 测试时，男双线允许女性填座，最低
   UTR 的女将把 pin 的和拉回 cap 内。改用 MD（混双，搭档限女）才逼出全 over-cap。
