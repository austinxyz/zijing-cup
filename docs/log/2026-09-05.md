### 起因

原来只有一个全局 `ADMIN_PASSWORD_HASH`，谁解锁都能改所有比赛，负责人没法把某组编辑权
单独交给该组队长。要按比赛（赛季+组别）分密码，各自只解锁对应比赛；负责人密码升级为 super
解锁全部。用户拍板：密码存 DB、scope 前端强制、super 复用现有 env、super 专属改密码界面。

### 做了什么（四组）

- **DB + 后端**：新表 `admin_credentials(season_year, division_code, password_hash, updated_at)`
  （`zijing_cup` schema，`(season,division)` 唯一）。GET 读 hash（受 `X-Backend-Secret`，登录前
  也只有 Next 能取）、PUT upsert（写方法自动加 `X-Admin-Secret`）。后端只存/回 `salt:hash`，
  绝不算/校验密码。
- **会话 scope**：`session.ts` 的签名载荷加 `scope`（`"*"` 或 `"<赛季>:<组别>"`），改 cookie 即失效；
  `readSession` 拒绝无 scope 的旧 token（fail-closed）。抽 `matches()` 共用给 super 与比赛校验。
  `authenticate(season, division, password)` 先比 super→`"*"`，否则比该比赛 DB hash→其 scope，
  都不中按原样失败（沿用限速）。
- **前端强制**：`canEdit(season, division)`（scope `"*"` 或恰好该比赛）；`adminWrite` 收目标比赛，
  盖不住就拒、不发 `X-Admin-Secret`，默认 `super-only`（漏传 fail-closed）；19 处写路径接线；
  就地解锁表单带 season/division。后端不变。
- **super 改密码页**：`/admin` 双门（页面 `isSuper` + server action 再校验 scope `"*"`），Next 侧
  scrypt hash → PUT。
