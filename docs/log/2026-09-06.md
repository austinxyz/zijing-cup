### 起因
队伍页编辑模式只能改已有队员字段，不能加/移出队员。后端 `add_membership`（POST）/
`remove_membership`（DELETE）/`create_player` 早就绪，只缺前端接线。分离自 player-admin-workbench
（那次明确排除、留作本 change）。

### 做了什么（三组）
- **g1 server actions**（`teams/[code]/actions.ts`）：`addExistingPlayerToTeam`（POST membership 带
  `team_id`）、`createAndAddPlayer`（先 POST /players，gender `""→null`，取回 id 再加入）、
  `removePlayerFromTeam`（`getPlayer` 按 `team_id` 定位 membership_id 再 DELETE，找不到抛错）、
  `searchPlayersForAdd`（`getPlayers({query})`，空 query→[]）。都经 `adminWrite` 按比赛 scope。
- **g2 UI**（`AddPlayerControl` + `TeamEditPanel`）：编辑模式加「加入队员」搜索控件（搜现有→加入本队 /
  新建姓名性别→新建并加入）+ 每行「操作」列「移出」→行内「确认移出/取消」。成功靠 server action
  `revalidatePath` 自动刷新；后端拒绝就地 role=alert。查看模式不渲染。补了两条「加/移被拒显示后端
  detail」的测（评审 group 2 的 MEDIUM）。
- **g3 验证**：前端 548、tsc 0、后端 566（回归，未改后端）、无 console.log；补种真实 2025 数据在
  BUAA-UMN-UCB 实测：搜 Li→60 命中、加 Li Amy 15→16、确认移出 16→15。

### 设计要点
- DELETE 要 `membership_id` 而 `RosterPlayer` 不带 → server action 用 `getPlayer` 按 team 定位（每队每人
  至多一条，唯一），保持前端-only、不改后端 roster 响应。
- 加入只建 membership，代表学校/外援/外卡加入后行内再填。
- `TeamRoster.team.id` 已存在，直接作 `team_id`，无需额外查。

### 无新 pitfall
纯前端接线，评审无 HIGH、无 attempt>1，未出现意外 foot-gun，CLAUDE.md 不加条目。
