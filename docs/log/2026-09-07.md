### 做了什么（三组）
- **g1 后端**：`PlayerNote` 模型（`created_at` server_default now() not null）+ migration（category CHECK
  in strength/weakness/partner/other、body 长度 1–2000 CHECK、`(player_id,created_at desc)` 索引）+
  `routers/players.py` GET 倒序 / POST 追加 / DELETE 删一条（无编辑端点）。鉴权靠方法判权中间件自动
  覆盖。10 条单测：追加不覆盖、倒序、category 拒、空 body 拒、超长拒 422、删一条、跨玩家不可删、
  GET 401/POST·DELETE 403。
- **g2 前端出口**：`lib/api.ts` `PlayerNote`（category literal union）+ `getPlayerNotes`（非 ok 降级 []）；
  players `actions.ts` `addPlayerNote`（body trim、空则 no-op）/`deletePlayerNote`，经 `adminWrite` scope
  `{season,division}`。
- **g3 详情「评价」区**：`NotesSection`（client）追加表单（`EditOnly` gate）+ 倒序时间线（类别中文标签+
  文本+时间+就地确认删除）+ 空态；机密门在 page 层——仅 `canEdit` 时 `getPlayerNotes` 取数并传入，
  未解锁传 `null` → 只渲染「评价是机密」占位、不发取数请求。真实数据 e2e 实测三类追加 + 删除确认 +
  机密门（后端日志确认未解锁不发取数请求）。
- **验证**：后端 pytest 577、前端 vitest 575（2 条 UtrPanel 并发时序 flake，隔离 8/8 过）、tsc 0、
  新源码无 console.log。
