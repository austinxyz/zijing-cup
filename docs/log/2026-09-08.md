### 起因
已存阵容能存、能重判、能改名/重排/克隆，但没地方记「这套打谁用、为什么这么排、注意哪条线」这类
主观注记。要一个随时间叠加、机密、挂在已存阵容上的评论流——跟球员评价一个模子。

### 做了什么（两组）
- **g1 后端**：`LineupComment` 模型（`created_at` server_default now() not null，避 SQLModel NULL 坑）+
  migration（`saved_lineup_id` FK saved_lineups on delete cascade、body 长度 1–2000 CHECK、
  `(saved_lineup_id, created_at desc)` 索引，`set search_path` 打头）+ `routers/lineups.py` GET 倒序 /
  POST 追加（`CommentIn` body trim 非空 + max_length 2000 挡 422）/ DELETE 按 (saved_lineup_id, id)
  删一条（跨阵容 404）——无编辑端点；批量 `GET /api/lineup-comments?ids=…`（扁平静态路径不与 `/{id}`
  冲突、按 saved_lineup_id 分组倒序、只放有评论的 id、去重/clamp≤200）。17 条单测：追加不覆盖、倒序、
  空/超长 422、删一条、跨阵容不可删、级联删、批量分组、鉴权 401/403、路由已注册断言。
- **g2 前端**：`lib/api.ts` `LineupComment` + `getLineupCommentsBatch`（空→`{}`不请求、非 ok/异常→`{}`
  降级）；`lineup/[code]/actions.ts` `addLineupComment`（body trim、空则 no-op）/`deleteLineupComment`，
  经 `adminWrite` scope `{season,division}`、`revalidatePath(.../lineup/{team}, "layout")` 盖排阵页 +
  `/saved` 两条路由。`LineupComments`（client）卡片内可展开区——**不是 body-portal 弹层**（躲触屏
  hover 坑）：折叠显示「评论 N」计数，展开倒序时间线 + 编辑模式追加框 + 逐条确认删除；gate =
  `useLineupEdit` 的 `canEdit && editing`。排阵页/`/saved` 页仅 `canEdit` 时按 saved id 批量取并传入。
- **验证**：后端 pytest 601、前端 vitest 620（2 条 TeamEditPanel/UtrPanel 时序 flake，隔离过）、tsc 0、
  新源码无 console.log；migration schema-qualified。真机 e2e：追加（中文正确渲染）+就地确认删除
  （计数 3→2）+克隆「副本」评论 0（clone-no-copy）+批量倒序 + 级联删（删阵容评论归零）实测过。

### 两个非显然的坑（已 sink 进 CLAUDE.md）
- **给评审 subagent 造 group diff 时 `git diff ... > f 2>&1` 把 git 的 CRLF 警告拼进了 diff**，
  评审据被污染的 diff 报「文件某行损坏 / 类型不匹配」的**假 BLOCK**——源文件干净、tsc 0、vitest 全绿。
  改用 `2>/dev/null`；BLOCK 先拿真跑结果对一下，矛盾就是 diff 假象（BLOCK 也不等于真坏）。
- **本机 curl `-d` POST 中文 mojibake**：e2e 用 curl 灌的评论页面渲染成 `?? THU ????`，一度当渲染 bug，
  但同屏 placeholder 中文正常——是 shell/curl 把 UTF-8 写坏了，非代码。走 app 写路径的中文正常。
  造中文测试数据用浏览器真实键入或 Python urllib，别用 shell curl。
