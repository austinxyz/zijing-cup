# lineup-page-defaults — 排阵页默认视图与就地编辑

四条对排阵页 (`/[season]/[division]/lineup/[code]`) 的改动，主题是「把这一页的
默认状态从『每次进来都整解一次』改成『先给你已经存好的，要算再算』，并让详情更
完整、编辑更就手」。

## Goals

1. **已存阵容优先。** 排阵页不再一进来就跑候选搜索。若该队有已存阵容，默认直接
   列出它们（沿用 `saved-lineups` 的四态重判呈现）；候选搜索按需触发。
2. **搜索显式化（草稿态 + `go`）。** 锁定/排除/pin 只有在用户点「搜索阵容」后才
   计算。URL 拆两态：不带 `go` = 草稿（只回显控件、不整解、可显示已存阵容），带
   `go=1` = 已请求（跑候选，行为同现状）。分享一条带 `go=1` 的链接照常直接出结果。
3. **载入 = 预填现有排阵控件，不新画界面；改后再搜、也能存。** 载入「已存阵型」把该
   套锁定/排除**预填进现在这套 `LineupControls`**（每条线**两个下拉**各选一名队员 +
   「锁整对」按钮，两个都选=锁定这对、只选一个=pin 交给引擎配另一半、都留「交给引擎」=
   整条交给引擎；下方「本场不能上」是全队名单的勾选格）。相对现状只两点变化：**(a)** 载入
   后**不自动搜**——URL 为草稿（无 `go`），点「搜索阵容」才计算；**(b)** 载入这套改完能
   **保存**（覆盖原阵型或另存），不必先搜出结果。控件本身不重画。
4. **统一「每条线 3 行块」详情，五线一行排开。** 已存阵容与候选阵容都用同一种每条线
   的三行块，且**五条线的块横向排成一行**以省纵向空间（窄屏再折行/单列）：
   - **行 1**：线名 + 该线参赛 UTR 之和 + 该线的 buffer 占用（超 cap 量，未超为 0）。
   - **行 2 / 行 3**：本线两名队员，**一人一行**，显示 姓名 + 性别（用符号 ♂/♀）+
     参赛 UTR。
   即每条线占三行、五条线并排为一套。性别不再只靠角标、UTR 不再要另查。
5. **就地解锁编辑。** 排阵页/已存阵容页加一个「编辑模式」开关：就地输入 admin
   密码即解锁已有的编辑能力（保存候选、删除/编辑已存阵容），免跳 `/login`。

## Non-Goals

- 不新增编辑能力本身（保存、就地互换/替换、存回都已在 `lineup-saved-lineups`
  落地）；#5 只是把入口从「跳 `/login`」改成「就地输密码解锁」。
- 不改后端合法性引擎、不改 `check_lineup`、不改鉴权模型（仍是 HTTP 方法判权的
  共享密钥 + 会话；就地解锁走**现有**登录 server action，只是换个触发位置）。
- 不做「草稿自动保存/跨会话记忆」——草稿就是当前 URL，不额外持久化。
- 不动 `/saved` 独立页是否保留的问题以呈现层决定（见 Open Questions）。

## Constraints

- **URL 仍是可分享的真请求。** `go=1` 的链接直接访问必须得到同一套候选（#2 不能
  退化成纯客户端草稿——那会丢掉分享与刷新，违背排阵页现有地基）。
- **草稿不即搜是 server 侧的事。** 页面是 server component；「有参不算」要由
  `go` 显式门控，不能靠客户端拦截（客户端拦不住直接访问带参 URL）。
- **前端不做数值比较**（UTR/cap/buffer 判定仍只信后端）。#4 只是显示后端给的数字。
- **就地解锁不新开信任入口。** 复用 `login` server action 与既有会话 cookie
  (httpOnly)、既有限速；写操作仍靠方法判权中间件保护。密码错/限速沿用登录的反馈。
- **冷启动。** 默认视图（已存阵容重判）在免费实例冷启动下也要能出；候选搜索仍是
  最慢的请求，只在 `go=1` 时才付这个代价——这正是 #1/#2 想要的省法。
- 桌面与 <768 都读得清、不横向溢出（长内容自带滚动容器）、对比度 ≥4.5:1、触摸
  目标 ≥44px。候选行内加 UTR/性别可能撑宽桌面对比表，需要自带横向滚动容器而非撑破页面。

## Success Criteria

1. 进入排阵页（无 `go`）、该队有已存阵容时：直接看到已存阵容四态列表，看不到候选
   列表，页面**没有**跑候选搜索（可由无候选请求/加载态佐证）。
2. 点「搜索阵容」→ URL 变为带 `go=1` + 当前控件参数 → 页面跑候选并显示；直接访问
   同一带 `go=1` URL 得到同一套候选。
3. 载入一套已存阵型 → 控件更新为该套锁定/排除、URL 是草稿（无 `go`）、**未**出现
   候选；随后点搜索才出候选。
4. 已存阵容与候选都用每条线三行块：行1 线名+和+buffer 占用；行2/3 每人一行含
   姓名+性别符号+UTR。桌面与 375 均不横向溢出。
5. 载入一套阵型后可继续改锁定/排除并保存（覆盖/另存），保存不要求先搜出候选。
6. 未登录时在排阵页点「编辑模式」→ 就地输入正确 admin 密码 → 解锁保存/编辑控件，
   无需离开该页；密码错走登录同款反馈；解锁后写操作生效。

## User Stories

- 作为队长，我常看的是那几套存好的阵容，进排阵页就想直接看到它们的当前状态，而不是
  每次等一遍整解；真要重新算再点搜索。
- 作为队长，我点开一套阵型想先看看它锁了谁，不想它一载入就又算一遍。
- 作为队长，我看候选时想直接看到每个人的 UTR 和性别，不用再去别处查。
- 作为管理员，我想在当前页直接输密码就能改，不想被踢去登录页再走回来。

## Open Questions

1. #1 的「已存阵容」是把 `/saved` 的内容并进排阵页默认视图，还是排阵页默认视图
   给一个醒目入口/内嵌其列表而 `/saved` 仍独立？（倾向：排阵页默认内嵌已存阵容列表，
   `/saved` 保留为深链接；propose 阶段定。）
2. 无已存阵容且无 `go` 时默认显示什么——空态提示 + 控件 + 「搜索阵容」，还是退回
   现状的自动搜索一次？（倾向：空态 + 控件 + 按钮，与 #2 一致，不自动搜。）
3. #4 候选行内 UTR/性别在桌面对比表里的具体排布（每格两行 vs 撑宽 + 横向滚动）——
   MOCK 阶段定。
4. 「编辑模式」开关放哪、解锁后如何显示已解锁态（复用侧栏已有的「管理员/登出」？）
   ——propose/mock 定。

## Referenced Capabilities

- `lineup-ui`（主要修改对象：默认视图、载入语义、候选详情、就地解锁入口）
- `lineup-search`（`go` 门控是否影响端点调用时机——只影响前端何时调用，不改端点）
- `lineup-saved-lineups`（已存阵容四态呈现、编辑器复用）
- `admin-access`（就地解锁复用登录 action 与会话，不改鉴权模型）
