# match-results-tracking — 录入已打比赛结果，作排阵参考

团体赛打完的对局，现在没地方记。本 change 让管理员录入一场**已打完的比赛**：我方某队 vs 对手队、
逐线用了谁、每线赢还是输。阵容可从某套已存阵容预填再临场调整，和 `saved_lineups` 脱钩独立存快照。
录完后在**对手对比页**看「我方对这支队打过什么、结果如何」，并有一个**比赛历史列表**人工翻查。
整场胜负按该组 `scoring_mode` 从逐线结果自动算。全部管理员机密。

## Goals

1. **录一场比赛。** 管理员录入：日期（必填）、我方队、对手队（同组另一支队）、轮次（可选自由文本）、
   我方逐线上场球员、对手逐线上场球员、每线 win/loss + 可选备注。写经 `adminWrite`（scope
   `{season,division}`）+ 成功 `revalidatePath`。
2. **阵容独立快照，可溯源。** 我方阵容存为比赛自己的快照 `{line: [player keys]}`（像 saved_lineup，
   不是外键引用某套），录入时可「复制自某套已存阵容」预填再改。存一个**可空** `source_lineup_id`
   仅作溯源（saved_lineup 后来被删/改名不影响历史）。
3. **对手逐线球员引用对手名单。** 对手上场球员逐线引用对手队当季名单里的 player；个别对不上（借将/
   名单不全）的**留空**，不强塞哨兵、不编造。
4. **逐线结果 + 整场自动算分。** 每线一个 win/loss + 可选自由文本备注。整场胜负由逐线结果按该 division
   的 `scoring_mode` 自动计算：银组（`match_count`）数赢的线数，金组（`points`）按线位 points 加权；
   该值只读、从不手填。
5. **对手维度露出。** 在对手对比页（`/compare`）看到「我方对所选对手队打过的历史对局」：各场日期、
   用的阵容、逐线结果、整场胜负。排阵时判断对某队什么管用。
6. **比赛历史列表。** 一个页面列该组所有录过的比赛（我方队 / 对手 / 日期 / 轮次 / 整场结果），可点进
   看逐线详情；支持按队筛选。兜底人工翻查。
7. **全管理员机密。** 录入和查看都按 `canEdit(season, division)` 门；免密队员一场都看不到（读路径对
   非管理员直接不取、不渲染）。

## Non-Goals

- **不做球员赢率聚合**（「某人上 D1 赢率」）——Q3 定先不做，以后单开 change。本 change 只到对手维度 +
   历史列表。
- 不做比分结构化（6-3/7-5）——细节塞逐线备注自由文本。
- 不公开给免密队员（不走 lineup-publish 那套公开开关）；以后要再加。
- 不回喂排阵引擎（不根据历史自动改候选/推荐阵容）——只做人读的参考。
- 不改 UTR 来源、不改排阵引擎、不加多用户登录。
- 不自动从外部（赛事官网/表格）抓比赛结果——纯手工录入。

## Constraints

- 架构不可违反：读经 `lib/api.ts` 单一出口，写经 `lib/admin.ts` 的 `adminWrite`；只有 FastAPI 访问库。
- 新表在 `zijing_cup` schema；migration `set search_path to zijing_cup, public;` 打头或全限定名、
  schema-qualified 外键、时间戳 `server_default`；**远程共享 Supabase 走 Dashboard 手工执行**
  （no-CLI-push），**push 读新表的后端前先在 Dashboard 建表**；前端/后端读路径对缺表降级（视作无历史，
  不 500——参照 preset 那条「只读旁支取数失败降级为空」）。
- 对手队必须是**同一 (season, division)** 的另一支队；外键/校验挡住跨组。
- 我方阵容快照、对手阵容快照都存可空 key（对不上的 player 留 null），读侧用「没有值」而非 0/哨兵表示
  （参照 CLAUDE.md「把『没有值』表达成 0 或哨兵不行」）。
- 整场结果**不落库手填值**，由逐线按 `scoring_mode` 计算（落库可缓存但以逐线为准，避免两处真相）。
- 写权限靠 `WRITE_METHODS` 方法判权中间件自动保护，不加前缀/依赖式鉴权。
- 日期按 LA 时区语义存/显示（参照快照时区那条教训，别用服务器 UTC 日期）。
- 多线位结果用结构化存储（每线 outcome + note + 双方球员），design 阶段定 JSONB vs 子表。

## Success Criteria

- 管理员录一场：选日期+对手+轮次、我方逐线填人（可先「复制自已存阵容」预填）、对手逐线填人、每线点
  win/loss、可加备注 → 落库。整场胜负按组别规则自动显示（银：3-2 之类线数；金：加权 points）。
- 对手对比页选中某对手队 → 下方多出「历史对局」区，列我方对该队打过的场次（日期/阵容/逐线结果/整场）。
  没打过则该区空、不报错。
- 比赛历史页列全部录过的比赛，可按队筛；点一场看逐线详情（双方球员 + 每线 win/loss + 备注）。
- 免密队员：录入入口不出现；对手对比页看不到「历史对局」区；历史页整个不可达（canEdit 门）。
- `source_lineup_id` 指向的 saved_lineup 被删后，历史对局仍完整显示（快照自存，不依赖外键存在）。
- 对手某线球员对不上名单 → 该线对手位显示「未记录」而非空白误导或 0。
- 缺表降级：新表未建时三处（录入、历史页、对手对比历史区）不崩，按「无历史」处理。
- 真实数据实测：录 1-2 场 → 对手对比页与历史页都正确显示；整场算分银/金各验一次。

## User Stories

- 作为队长，我想把上周打完的那场（我方 UCSD-ZJU vs THU-MIT，D1 赢、MD 输…）记下来，含双方上场的人。
- 作为排阵的人，我在给某对手排阵时想先看「我方以前对这支队怎么排的、哪条线赢过」。
- 作为管理员，我想翻一个列表看所有录过的比赛，点进去看某场的逐线细节和当时双方阵容。
- 作为管理员，我不想手算整场几比几——录完逐线，系统按组别规则自动给我整场胜负。

## Open Questions

- 录入表单布局：逐线「我方两人 / 对手两人 / win-loss / 备注」一行，还是分我方块+对手块？——Phase 4 mock 定。
- 对手对比页「历史对局」区的位置（picker 下方？独立折叠块？）与折叠默认态——Phase 4 定。
- 历史列表页进入口（侧栏加一条？还是挂在对手对比/队伍页）——Phase 4 / propose 定。
- 一场比赛的线位集合是否固定等于该 division 的 `division_lines`（应是——按组别线位逐行录），确认无「自定义线」需求。

## Referenced Capabilities

- 新 capability `match-results`（比赛记录表 + CRUD 端点 + 整场算分 + 历史/对手维度读）。
- `lineup-saved-lineups`（录入时「复制自已存阵容」预填来源；`source_lineup_id` 溯源）。
- `opponent-compare` / `opponent-compare-enhance`（对手对比页挂「历史对局」区）。
- `app-shell` / `scoped-admin-auth`（canEdit 门、adminWrite scope、缺表降级范式、侧栏入口）。
- `players` / `roster`（我方与对手逐线球员引用名单 player）。
