## Context

`LineupResults.tsx` 现在把每套候选渲染成一张 `CandidateCard`：96px 总和列 + 五个
`flex-1` 线列，每列「name男 + name男」+ 该线之和。窄列让名字换行（实测一对 ~116px 高、
整卡 ~177px），20 套叠成 ~3500px。用法是「快速扫、挑一套」，而 Top 几套常同分，靠搭配
与关键人位置区分——现在搭配被挤得读不了、跨套又不能对齐比。

本次纯前端重排，不动后端、搜索、数据。`LineupCandidate`（`total` / `buffer_spent` /
`lines` / `line_totals`）已够用；后端 `keep=20`，候选至多 20 套。

`LineupResults` 里除候选列表外还有：顶部摘要区（可达上限等）、未裁决/缺 UTR 提示、
无解/非法锁定/截断面板——**都不在本次范围**，只换「有候选」时的候选列表那一段。

## Goals / Non-Goals

**Goals:**
- 桌面候选 → 对比表，列对齐可竖扫、同分不同搭配一眼分辨。
- 手机候选 → 紧凑行 + 点开五线。
- 既有合法性信号一个不丢（估算两处、超 cap、buffer、性别、开放线）。

**Non-Goals:**
- 关键人高亮（后续单列）。
- 顶部摘要区、非正常态面板、后端、排序/去重/keep。

## Decisions

### D1 桌面用真 `<table>`，不是 flex 拼的伪表

对齐是这次的价值——竖扫「谁在 D1」要求同列跨行左边缘严格对齐。真 `<table>` +
`table-fixed` 天然给列宽一致；flex 拼的每行各自算宽，对不齐。`table-fixed` 还让长名
在固定列宽里截断（`overflow:hidden` + `text-overflow:ellipsis`）而不是把表推宽。

表头钉住用 `position:sticky; top:0`。表体滚动容器沿用既有模式（壳 `overflow-hidden`，
内层自带滚动）。

### D2 手机不是「把表塞进窄屏」，是另一套紧凑行 DOM

五列在 375px 放不下、跨套对齐在窄屏也做不到，所以手机是逐行紧凑列表（名次+总和+D1
签名+代价角标），点开展开五线纵向堆叠。与 mobile-shell 的名单卡片同一路子：两套 DOM
由 `md` 断点 `hidden`/`md:*` 切，不按 user-agent。

**签名取 D1 搭配**：同分时 D1 最能代表一套的取向；代价角标（含估算/超cap）让收起态也能
看出「有戴的那套」。

### D3 判定逻辑抽成共用纯函数，两套 DOM 只排版

估算标记、超 cap、buffer 文案、性别、开放线——这些「怎么判、显示什么字」抽成纯函数
（如 `candidateFlags(candidate)` / 现有的 `estimatesIn` / `money`），桌面表格与手机行
都调它。会分歧的只是排版，不是判定。这也是 mobile-shell 名单两套 DOM 用过的办法。

### D4 密集视图用紧凑估算标记 + 图例，完整措辞不删只挪

既有 spec 要求「整套逐字呈现 `含 N 个估算值，合法性待总表确认`」「数字旁逐字 `估算`」。
40px 的表格行放不下整句。解法：桌面表里数字用一个小角标（`˟`）、整套用总和格一个
「估」badge，底部一条**图例**给出完整措辞；手机紧凑行用「含估算」角标，展开态可给整句。
**规则**：标记在每个该标的地方都在（不因紧凑而省略），完整措辞在够得到处（图例/悬停/
展开）保留一处——不是删，是从每行挪到一处。这条已写进 MODIFIED 的 spec。

### D5 不重排候选（既有不变式，保留）

按 `search.candidates` 顺序渲染。同分是常态，二次排序每次渲染挑不同赢家——既有约束，
测试已锁，本次照旧。

## Risks / Trade-offs

- **[两套 DOM 会分歧]** 表格与紧凑行各写一套 → 改字段容易只改一边 → 判定抽成共用纯
  函数，两套只排版；测试断言同一候选在两视口给出同样的标记集合。
- **[table-fixed 列宽 + 长名]** 列宽固定后特别长的中英文名会截断得早 → 名字列给足
  相对宽度（五线均分剩余），并 `title` 挂全名；视觉核对用最长真实名（26 人队）。
- **[表头 sticky 在既有滚动容器里]** sticky 要相对滚动容器生效，容器/表结构没套对
  会导致表头不钉 → 实现后实测滚动时表头 top:0 不动（VISUAL DIFF 量）。
- **[对比度]** 新表/行的次要文字若用 `--color-muted` 类 token，底色要显式给 `bg-surface`
  否则页面底色上 4.27 不合格；硬编码颜色对（如角标）要量——稿子已撞到 `#a09a90` 2.79，
  改 `#706a61`。实现按稿子的值。

## Migration Plan

纯前端，无数据库、无 API、无环境变量变更。Vercel 部署即生效，回滚即回滚上一个部署。
桌面/手机用户看到的是候选区版式变化；顶部摘要与其余页面不变。
