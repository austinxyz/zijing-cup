# mobile-shell

现在**所有页面都是桌面三栏**：216px 深色侧栏 + 一条中间列（球队列 / 排阵控件）+ 主体。
壳是 `h-screen min-h-[640px] overflow-hidden`，横向不折行、纵向不滚动。手机上打开会
横向溢出，而 `overflow-hidden` 让溢出部分**不出现滚动条** —— 看不出还有内容。

真实使用场景恰恰在手机上：比赛当天在场边看名单、临时改阵容、临时补一个人的 UTR。
在电脑前的场景（导名单、批量导 UTR、合并拆分队员）已经有桌面版式了。

本次把**读路径**（赛制规则 / 球队列表 / 球队名单 / 排阵）做出手机版式，顺带补一条
一直缺的东西：`utr_profile_id` 存了却从来没有一处是真链接。

## Goals

- **< 768px 时侧栏收成顶栏 + tab 条**，三栏结构在手机上变成逐屏钻取。
- **球队列表与球队名单是两屏**，名单页带「‹ 球队」返回。
- **排阵页在手机上以结果打底**，锁定/排除控件收成一个可展开面板，关上就回到结果。
- **名单行在手机上留：序号 · 姓名+性别 · 参赛 UTR + 来源标签**。参赛 UTR 是决定阵容
  合不合法的那个值；来源标签说清它是冻结值还是估算（估算时说清估自哪儿）。
- **UTR 官网链接**：有 `utr_profile_id` 的人可以一点跳到他的 UTR 档案页。**桌面也加**，
  三处，各自情况不同：
  - 名单页（`teams/[code]`）姓名变链接 —— 桌面这张表**此前完全没有** profile 的踪影，
    这是新增元素，不是「文字变可点」；
  - 队员详情页（`players/[id]`）那行 `…/profiles/{id}` 文字变真链接；
  - 队员列表（`players/PlayerTable`）那列的「有」变链接（「无」照旧是纯文字）。
- 管理员的**行内编辑在手机上保留**：场边补一个人的当前 UTR 是真实动作，而行内编辑正是
  「改一个人」那条路径（批量往返表是电脑上的事）。功能必须在；**形态**与桌面不会一样
  （桌面是表格行里的 inputs，手机名单不是表格），见 Open Question 4。

## Non-Goals

- **管理类界面不做手机版式**：队员管理（列表 / 详情 / 未裁决 / 合并 / 拆分）与 UTR
  批量导入往返表照旧是桌面三栏，手机上打开要横向滚动。这是明确取舍，不是遗漏。
- **队员管理不上手机 tab 条**。后果要写明：手机上没有任何入口能到达队员管理。
- **冷启动加载态不在本次**，单独一个 change。它与版式没有技术依赖，且它自己带一个
  已知地雷（见 Constraints）—— 混在一起会让本次评审同时背两个风险。
- **不改任何后端**。`utr_profile_id` 早就在两个只读端点的响应里，链接是纯前端拼接。
- 不做原生 App、不做 PWA、不做离线。
- 不动桌面版式的任何**布局** —— 行高、列数、列宽都不变。桌面上会变的只有两样：
  上面那三处多出可点的 UTR 链接，以及下面「两个 token 的对比度」那条。注意三处链接里
  有两处在队员管理下：管理界面**不做手机版式**，但它上面的链接照加，两件事互不牵连。

## Constraints

### 架构（不可违反，见 CLAUDE.md）

- 浏览器只与 Next.js 通信；取数仍走 `frontend/lib/api.ts` 单一出口。
- 本次不新增任何端点，不碰数据库。

### 断点

- **< 768px 走手机版式**（Tailwind 默认 `md`）。不引入自定义断点。iPad 竖屏走手机版式，
  横屏走桌面三栏。

### 高度模型要重定，不能沿用桌面那套

壳现在是 `h-screen min-h-[640px] overflow-hidden`：

- `100vh` 在手机浏览器上按**地址栏收起后**的高度算，页面因此比可视区高一截；
- `min-h-[640px]` 在矮屏上直接把内容顶出可视区；
- 而 `overflow-hidden` 让上面两件事**静默发生** —— 内容被裁掉且不出现滚动条。

这不是猜的：同一个缺陷在桌面上交付后才被发现（`h-screen overflow-hidden` 的壳里，
任何可能变长的列表都必须自带滚动容器，否则超出部分被无声裁掉）。手机版式必须显式决定
这一层用什么（`100dvh`、去掉 `min-h`、或改成整页滚动），并在**最长数据 + 最矮视口**下
核对。最长名单是 2025 赛季的 26 人。

### 不许用路由级 `loading.tsx`

`loading.tsx` 让 Next 在页面代码跑之前 flush 响应头，于是 `notFound()` 再也设不了
状态码 —— 实测同一个未知球队，有它返回 200、去掉返回 404。同一批实测里 fallback
还始终没被替换（生产构建也一样）。本次不引入任何路由级 Suspense 边界。

### 每条新路由自带 `error.tsx`

本次预计不新增路由（版式改在现有路由上）。若最终切出了新路由，它必须自带
`error.tsx` —— 根 `error.tsx` 替换的是整个窗口，一次冷启动超时会从「某一块加载失败」
变成「整个应用崩了」。实测方法：把 `BACKEND_URL` 指到一个没人监听的端口。

### 顶栏是页面外壳，有自己的配色

深色壳里不要用内容区的颜色 token。赛季切换器的药丸底色曾写成 `bg-background`（浅色
内容区底色 `#f6f4f0`），配近白标签只有 1.05:1。侧栏用的是 `--color-sidebar-*` 与
`--color-sidebar-well`，顶栏沿用同一组。

### 顺带修两个既有 token 的对比度（画稿时量出来的）

这两条**不是本次引入的**，是画视觉稿逐节点量 computed style 时撞上的，两处都在今天的
桌面上跑着。负责人拍板本次一起修 —— 手机稿要求「全部 ≥ 4.5:1」，而这两个 token 正是
手机屏上要用的，绕不过去。

| token 组合 | 现在 | 改成 | 改后 | 出现在 |
|---|---|---|---|---|
| `--color-muted` #79736a on `--color-surface-muted` #f2efe9 | **4.09** | `--color-muted` → #6b665d | **4.97** | 所有表头（`rules/page.tsx:108`、`RosterTable.tsx:407`、`players/[id]/page.tsx:108`）与安静档徽章 |
| `--color-sidebar-fg-dim` #6f6a60 + `opacity-45` on `--color-sidebar` #1c1b18 | **1.63** | 去掉 `opacity-45`，dim → #8f8a7e | **5.01** | `Sidebar.tsx:69/75` 的 `PendingNavItem`（「对手对比 · 未开放」） |

第二条那个 1.63:1 是**合成后**的值（#6f6a60 以 45% 不透明度压在 #1c1b18 上得
#413f38）—— 侧栏那个「未开放」项现在基本看不见，与用户上次截图报上来的赛季药丸
1.05:1 是同一类错误：**光看源码里的 token 名判断不出够不够，要量合成后的实际颜色**。

`--color-muted` 改深会波及桌面 ~76 处用到它的地方，全部是变深一点，不改布局。

### 对比度按 computed style 量

所有文案 ≥ 4.5:1，量 computed style 而不是照源码估。`--color-muted` 在白底 4.69、
在页面底色 `#f6f4f0` 上 4.27 —— 够不够看**取决于容器有没有给自己底色**，这件事在
源码里看不出来。新做的面板显式给 `bg-surface`。

### 触摸目标

可点行与 tab 至少 44px 高。桌面现在的导航行是 34px。

### UTR 链接

- 模板 `https://app.utrsports.net/profiles/<utr_profile_id>`，**全站一个常量**。
- `utr_profile_id` 为 null 时不渲染链接，也不渲染一个点不动的壳子。
- 外链带 `rel="noopener noreferrer"`。
- `utr_profile_id` 由人手工维护，线上填充率**未知**且不影响设计 —— 见下面「已解决」
  一节。按大面积为空设计，验收要看这个状态下页面长什么样。

### 测试

- `npm run test` 不做类型检查（vitest 走 esbuild 只转译）。`npx tsc --noEmit` 单列。
- `npm run lint` 当前跑不起来（ESLint 加载配置即崩），这条防线是空的，别把它的沉默
  当成 lint 干净。
- **本地看页面之前不要跑 `pytest`** —— 它会 TRUNCATE 规则表与名单表，跑完页面全 404。
  顺序写死：先跑测试 → 再补种（`bash backend/scripts/reseed-local.sh`）→ 再做视觉核对。

## Success Criteria

1. 375px 宽的视口下，五条读路由（`/rules`、`/teams`、`/teams/[code]`、`/lineup`、
   `/lineup/[code]`）**没有一条横向滚动**，也没有内容被裁掉而不出现滚动条。
2. 在 375×**667**（矮屏）下核对 2025 赛季最长名单（26 人）：能滚到最后一行，且滚动
   来自一个真实的滚动容器 —— 不是内容溢出被 `overflow-hidden` 静默裁掉。（页头/表头
   是否吸顶见 Open Question 3，本条不预设。）
3. 手机上球队列表与球队名单是两屏；名单页有返回球队列表的入口；桌面仍是并排两列。
4. tab 条四项：队伍 / 阵容 / 对手对比（禁用，标「未开放」）/ 赛制规则。「队员管理」
   不出现。当前所在项有选中态，且选中态由 URL 推导而非组件状态。
5. 赛季×组别切换器在手机顶栏可用，列出全部组合，当前项标记且不可点。
6. 排阵页在手机上首屏看到的是 Top-5 结果；约束面板可展开、可关上；关上后能看到当前
   锁定/排除的摘要（不是「点开才知道有没有约束」）。
7. 名单行显示参赛 UTR 与来源标签：`frozen` 不标；`current_doubles` 标「估算 · 当前
   已认证值」；`prior_season` 标「估算 · <年> 参赛值」。参赛 UTR 为 null 的队员**仍然
   出现在名单里**，显示「无参赛 UTR」而不是 0、也不是被跳过。
8. 有 `utr_profile_id` 的人在**手机与桌面**都能点开 UTR 官网档案页；没有的人不显示
   链接、也不显示一个点不动的壳子。三处都覆盖：名单页姓名、队员详情页那行
   `…/profiles/{id}`、队员列表那列的「有」。网址来自同一个常量（测试断言只有一处
   字面量）。
9. 管理员在手机上能行内改一个人的当前单/双打 UTR，改完页面上看得见。
10. 所有文案对比度 ≥ 4.5:1（实测 computed style，报告不合格元素数为 0）。含两条既有
    缺陷的修复断言：`--color-muted` 在 `--color-surface-muted` 上 ≥ 4.5（改前 4.09），
    侧栏「未开放」项**合成后**的实际颜色 ≥ 4.5（改前 1.63）。视觉稿实测基线：370 个
    叶子节点、0 个不合格、最低 4.69。
11. 桌面版式（≥ 768px）**布局**逐屏与改动前一致：差别只有那三处多出的 UTR 链接，
    以及两个 token 变深/变亮后的颜色。行高、列数、列宽不变。
12. `npx tsc --noEmit` 干净；`npm run test` 与 `uv run pytest` 全绿。

## User Stories

- 作为队长，比赛当天我在场边掏出手机想看对面那支队的名单，我希望一屏就能翻，而不是
  横着拖一张为 1440px 画的表。
- 作为队长，我在场边临时想调一下阵容，我希望先看到排出来的阵容，改约束是我主动去点的
  那一下，而不是每次都先滑过一屏控件。
- 作为队长，我看到某个人的参赛 UTR 是 6.35，我想知道这是组委会冻结的值还是系统估的；
  如果是估的，估自哪儿。
- 作为队长，我对某个人的 UTR 有疑问，我想一点就跳到 UTR 官网他的档案页去对，而不是
  自己去搜名字。
- 作为管理员，场边有人报了一个新的 UTR，我想在手机上就把它填进去。

## 已解决（探索阶段定掉的两条）

### 手机上的「两屏」用 CSS，不拆路由 —— 这不是取舍

**服务端看不见视口**。Next 在服务器上渲染 layout 与 page，那里没有屏幕宽度这个信息。
按设备拆路由只能靠 user-agent 嗅探，而 UA 不可靠、还会把同一个 URL 的缓存按设备切开。
所以球队列表/名单在手机上是「同一套路由 + CSS 决定哪一列可见」，与桌面共用一份代码。

代价说清楚：手机在名单屏也下载了球队列的 HTML（18 行，不大）。**不产生额外延迟** ——
`teams/layout.tsx` 取球队列、`teams/[code]/page.tsx` 取名单，Next 并发渲染两者，冷启动
时它们是一次等待而不是两次。

### `utr_profile_id` 的填充率未知，且不影响设计

线上连接串在 Render 控制台、仓库里没有，探索阶段**没有测到**这个数字。因此按最保守的
状态设计：**假设大部分人没有链接**。空态必须看起来是有意的（不渲染一个点不动的壳子，
也不显示报错），有链接的人才多一个入口。填充率无论是 5% 还是 95%，设计都不变 ——
这条因此不再是待定项。

## Open Questions（全部留给 Phase 4 视觉稿，不阻塞 propose）

1. 排阵页的约束面板形态 —— 底部抽屉、全屏覆盖、还是顶部展开。
2. 面板收起时那条约束摘要写什么：「已锁 2 对 · 排除 1 人」够不够，还是要点名是谁。
3. 顶栏在向下滚动时是否吸顶。名单 26 人要滑很久，吸顶能一直看到当前是哪支队；代价是

4. 管理员在手机上编辑一个人的形态。桌面是表格行里的 inputs，而手机名单不是表格 ——
   多半是「点开那一行 → 一个编辑面板」。功能必须在（已定），形态待稿。

## Design System

沿用项目现有设计系统（`openspec/config.yaml` 的 `design_system: linear`，token 在
`frontend/app/globals.css`，逐值移植自 ai-course-management）。**不重新选设计系统** ——
项目早就定了，再选一次等于给自己开个漂移的口子。

**不新增 token**，只改两个既有值（见 Constraints 里那张表）。顶栏用侧栏那组
`--color-sidebar-*` 与 `--color-sidebar-well`，不从内容区借 —— 桌面上从内容区借
`bg-background` 造成过 1.05:1。

视觉稿：`docs/superpowers/specs/mocks/2026-08-31-mobile-shell-mocks.html`，七屏，
全部画在 **375×667**。实测基线：370 个叶子节点、0 个低于 4.5:1、最低 4.69；球队屏
18 队溢出 428px、名单屏 26 人溢出 1178px（滚动容器真的被触发，顶栏不跟着卷走）。

`design/` 下那三张旧手机稿（`TeamsMobile` / `TeamsMobileRoster` / `RulesMobile`）
**作废**：tab 条是旧的三项、名单画在「当前单/双打」两列存在之前、也没有 UTR 链接。

## 探索阶段测得的事实

- 桌面每条路由的列数：`/rules` 两列；`/teams` 与 `/teams/[code]` 与
  `/teams/[code]/utr` 三列（球队列在 `teams/layout.tsx`）；`/lineup` 两列；
  `/lineup/[code]` 三列（`LineupControls` 是客户端组件）；`/players*` 两列。
- 壳在 `app/[season]/[division]/layout.tsx`：`flex h-screen min-h-[640px]
  overflow-hidden bg-background`，侧栏 `w-[216px] flex-none`。
- 导航选中态已经由 `useSelectedLayoutSegment()` 从 URL 推导（`ActiveSidebar`），
  球队列的选中态同理（`SelectedTeamList`）。手机 tab 条可以复用这条路子。
- 桌面名单表 7 列：序号 / 姓名 / 性别 / 参赛 UTR / UTR 来源 / 当前单打 / 当前双打。
- **`utr_profile_id` 全站没有一处是真链接**：`players/PlayerTable.tsx` 渲染成
  「有 / 无」，`players/[id]/page.tsx` 渲染成文字 `…/profiles/{id}`，UTR 往返表把它
  当一列数据导出。代码库里没有任何 UTR 网址常量。
- `RosterPlayer.match_utr` 与 `origin` 都可空（`read-path-switch` 放宽的）：一名队员
  可以在队但一个数都取不到，且这种人**必须出现在名单里** —— 否则球队列的 `player_count`
  与名单条数对不上而页面不说。
- `origin` 取值 `frozen` / `current_doubles` / `prior_season`；`origin_year` 对
  `current_doubles` 为 null（它不是一个赛季的值）。
