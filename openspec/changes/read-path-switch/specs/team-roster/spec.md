## MODIFIED Requirements

### Requirement: 提供按赛季组别查询球队与名单的只读端点
后端 SHALL 提供球队列表与球队名单两个只读端点。球队列表 SHALL 为每支球队
带出名单人数与按性别的人数分布；性别为空的记录 MUST 单独计数，MUST NOT
并入任一性别。两个端点 SHALL 带出球队的显示名（未配置时为空）。系统
MUST NOT 提供任何修改名单或球队的 HTTP 端点 —— 名单的写入路径是队员管理，
在那里改，不在这里改。

两个端点的数据来源 SHALL 是**队员注册表**（队员 / 赛季参赛 UTR / 队伍成员关系），
MUST NOT 再读名单快照 `roster_entries`。名单的「人数」自此等于该队的成员关系条数，
性别取自队员记录。

名单端点 SHALL 带出每名队员的**当前**单打 / 双打 UTR 及其各自状态。这四个值是推导链
第二步的输入：没有它们，看的人无从判断某个估算为什么落在那里，也无从在本赛季参赛 UTR
出来之前自己先估一个。四者未填时为 null。

其余字段集合 SHALL 保持不变。`dutr_status` / `source_note` / `daily_utrs` 在新来源里
没有对应物，因此恒为 null —— 保留字段是为了不改变响应形状，**消费方 MUST NOT 从它们
身上推断任何事实**：一个恒为 null 的字段读起来是「总表没说」，而事实是「系统不再存它」。

一名队员在该赛季没有参赛 UTR 时，端点 SHALL 返回按推导链取得的值及其来源标记
（见 `lineup-search` 的「参赛 UTR 的推导链」），MUST NOT 把推导值呈现得与冻结值无异，
也 MUST NOT 因为缺值就把这名队员从名单里略去 —— 他确实在队里。

推导链一个值都取不到时，该队员 SHALL 仍然出现在名单里，参赛 UTR 与来源同为 null。
MUST NOT 用 0 或任何哨兵值代替 —— 0 是一个合法 UTR，看的人分辨不出来。球队列表的人数
与名单的条数 SHALL 始终一致：两者对不上而页面又不说，读的人无从知道少了谁。

#### Scenario: 查询球队列表
- **WHEN** 请求某个存在的赛季组别的球队列表
- **THEN** 返回 200 与该组别的球队清单
- **AND** 每支球队带有总人数、按性别的人数分布与显示名

#### Scenario: 性别分布与总数自洽
- **WHEN** 读取球队列表中任一球队的人数
- **THEN** 男、女与性别未填三项之和等于该球队的总人数

#### Scenario: 人数来自成员关系
- **WHEN** 管理员把一名队员加入某支球队
- **THEN** 该球队在列表中的总人数增加一

#### Scenario: 查询球队名单
- **WHEN** 请求某支存在球队的名单
- **THEN** 返回 200 与该队全部队员，含参赛 UTR、评级类别、外援标记与该值的来源
- **AND** 响应带有该球队的 code 与显示名

#### Scenario: 管理界面的修改在名单里可见
- **WHEN** 管理员改动一名队员的姓名或该赛季的参赛 UTR 后重新请求名单
- **THEN** 返回的是改动后的值

#### Scenario: 缺值队员仍在名单里
- **WHEN** 某名队员在该赛季没有参赛 UTR，但按推导链能取到一个值
- **THEN** 该队员出现在名单中，参赛 UTR 为推导值
- **AND** 响应标明这个值是推导来的以及依据的是哪一年

#### Scenario: 一个值都取不到的队员仍在名单里
- **WHEN** 某名队员既无该赛季值、无当前已认证双打值，也无任何更早赛季的值
- **THEN** 该队员仍出现在名单中，参赛 UTR 与来源均为 null
- **AND** 球队列表里该队的人数与名单条数一致

#### Scenario: 名单带出当前 UTR 与其状态
- **WHEN** 请求某支球队的名单
- **THEN** 每条记录带有当前单打 UTR、单打状态、当前双打 UTR、双打状态
- **AND** 四者未填时为 null，MUST NOT 以 0 或空串代替

#### Scenario: 旧字段恒为空
- **WHEN** 读取任一名单记录的 `dutr_status` / `source_note` / `daily_utrs`
- **THEN** 三者均为 null

#### Scenario: 未知球队
- **WHEN** 请求一支不存在的球队的名单
- **THEN** 返回 404 而非空列表

#### Scenario: 未知赛季或组别
- **WHEN** 请求不存在的赛季或组别代码
- **THEN** 返回 404

#### Scenario: 不存在名单的写方法
- **WHEN** 检查应用暴露的 HTTP 接口
- **THEN** 不存在任何指向名单或球队资源的 POST / PUT / PATCH / DELETE 方法

## ADDED Requirements

### Requirement: 名单导入器在读路径切换后拒绝运行
导入器 SHALL 拒绝执行，或在执行前后**刺眼地**说明这些行不会出现在任何页面上——
名单 CSV 导入器写入的 `roster_entries` 在本 change 之后不再被任何读取路径消费。
MUST NOT 只输出「+N 行」——那是一次成功的假象：命令报告写入了数据，而网站上什么都
没变，读到这条输出的人会去别处找原因。

拒绝 SHALL 可以被一个显式的开关绕过（例如 `--i-know-it-is-not-read`），供需要往旧表
补数据的场合使用；绕过时仍 SHALL 打印同一条说明。

#### Scenario: 默认拒绝
- **WHEN** 在读路径切换之后运行名单导入命令
- **THEN** 命令不写入任何数据并以非零码退出
- **AND** 输出说明这些行不会被任何页面读取，以及应当去哪里改名单

#### Scenario: 显式绕过仍然说明
- **WHEN** 带着显式开关运行导入命令
- **THEN** 数据照常写入 `roster_entries`
- **AND** 输出仍然说明这些行不会被任何页面读取
