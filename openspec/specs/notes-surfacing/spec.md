# notes-surfacing Specification

## Purpose
把已有的球员评价（`player-notes`，机密、挂人、跨赛季）只读地展示到排阵页（候选卡 + 已存阵容）、
对手对比、队伍 roster 三个决策界面，作为排阵的参考信号（展示 + 轻提示），不改引擎、不改合法性判定、
不改推荐排序。

## Requirements

### Requirement: 批量读评价端点

系统 SHALL 提供一个按 player id 列表批量返回评价的只读端点，供一个界面上的多名球员一次往返取回，
避免每人一次请求。端点按 player_id 分组返回评价，每名球员的评价按 `created_at` 倒序。

#### Scenario: 一次取回多名球员的评价
- **WHEN** 请求 `GET /api/players/notes?ids=1,2,3`（带 backend secret）
- **THEN** 返回一个按 player_id 分组的映射，键是请求中有评价的 player_id，值是该球员的评价数组（倒序）

#### Scenario: 无评价或不存在的 id 不占键
- **WHEN** 请求的某个 id 没有任何评价（或不存在）
- **THEN** 该 id **不出现**在返回映射里（调用方据「键缺失」当作「无评价」），而不是返回空数组或报错

#### Scenario: 空 ids 请求
- **WHEN** `ids` 为空或缺省
- **THEN** 返回空映射，不报错

#### Scenario: 读端点走 backend secret
- **WHEN** 请求不带 `X-Backend-Secret`
- **THEN** 被中间件拒（与其他读路由一致）；本端点是读操作，不需要 admin secret

### Requirement: 机密门 —— 仅解锁本比赛才取数与展示

三个界面 SHALL 按 `canEdit(season, division)` gate 评价的展示：仅当会话可编辑本比赛时，页面才批量取
评价并渲染标记；未解锁时 MUST NOT 发批量取评价请求、MUST NOT 渲染任何评价标记或内容。对手对比
两侧（我方与对手）在解锁后都展示评价。

#### Scenario: 未解锁不取不显
- **WHEN** 会话未解锁本比赛，打开排阵/对手对比/roster 任一
- **THEN** 不发批量取评价请求，页面不出现任何评价标记；球员行/seat 照常显示其余信息

#### Scenario: 解锁后对手对比两侧都显示
- **WHEN** 会话已解锁本比赛，打开对手对比
- **THEN** 我方与对手两侧的球员都按其评价显示标记（看对手评价是侦查目的）

#### Scenario: 取数失败降级、不拖垮宿主页
- **WHEN** 批量取评价请求失败（如网络错误或端点不可用）
- **THEN** 三处降级为「无评价」（不显示标记），排阵/对比/roster 主功能照常，不整页报错

### Requirement: roster 与对手对比用分类小标

在队伍 roster 每行、对手对比两侧逐线的每名球员旁，系统 SHALL 显示一组按类别的小标：优点（正色）、
弱点（警示色）、搭档（蓝）、其他（灰），类别用中文标签。没有评价的球员 MUST NOT 显示任何小标
（不占位、不留空标记）。

#### Scenario: 有评价按类别显示小标
- **WHEN** 某球员有优点与弱点各若干条，页面已解锁
- **THEN** 该球员旁显示「优点」正色小标与「弱点」警示色小标；弱点一眼可辨

#### Scenario: 无评价不显示
- **WHEN** 某球员没有任何评价
- **THEN** 该球员旁不显示任何小标

### Requirement: 排阵 seat 用单标记「评」

排阵页候选卡与已存阵容的每个 seat（经共享 `LineBlock`）空间极窄，系统 SHALL 显示一个单标记「评」
（与既有 外/▲/估 内联标记同族）表示该球员有评价：含弱点时用警示色、否则中性色；无评价不显示。
改动 SHALL 只在共享 `LineBlock` 一处，使候选卡与已存阵容同时生效、读起来一致。

#### Scenario: 含弱点的 seat 警示色
- **WHEN** 某 seat 的球员有一条弱点评价，页面已解锁
- **THEN** 该 seat 显示警示色的「评」标记

#### Scenario: 有评价无弱点的 seat 中性色
- **WHEN** 某 seat 的球员有评价但无弱点类
- **THEN** 该 seat 显示中性色的「评」标记

#### Scenario: 候选与已存一致
- **WHEN** 同一球员同时出现在候选卡与已存阵容
- **THEN** 两处都显示同一个「评」标记（同一 `LineBlock` 渲染）

### Requirement: 共用只读时间线弹层

三处的评价标记（分类小标与 seat「评」）点/悬停时 SHALL 打开**同一个**评价时间线弹层：倒序（最新在上）、
每条含类别中文标签 + 文本 + 时间。弹层 MUST 只读——追加/编辑/删除 MUST NOT 出现在此弹层，写操作仍
只在球员详情页。桌面悬停触发、移动点开触发；弹层内容超出时自带滚动。

#### Scenario: 点开看倒序时间线
- **WHEN** 点/悬停某球员的评价标记
- **THEN** 弹出该球员评价的倒序时间线（类别标签 + 文本 + 时间），无任何追加/删除控件

#### Scenario: 移动端点开
- **WHEN** 在移动端（悬停不可用）点评价标记
- **THEN** 弹层以点击打开，内容多时自带滚动，不撑破页面壳

### Requirement: 纯展示，不影响排阵逻辑

评价的展示 MUST NOT 改变排阵引擎、合法性判定、候选生成/排序、任何推荐或打分。评价是主观自由文本，
「搭档」类别无结构化球员引用，系统 MUST NOT 声称「你排进来的正是推荐搭档」这类自动匹配——信号只
表达「此人有某类评价存在」。

#### Scenario: 展示不改候选
- **WHEN** 给球员记了评价后重新排阵
- **THEN** 候选集合与排序与未记评价时完全一致；评价只是叠加的视觉标记
