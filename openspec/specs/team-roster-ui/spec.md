# team-roster-ui Specification

## Purpose
让队长在浏览器里翻名单，取代「打开 Google Sheet 用眼睛找」。左侧常驻球队列，
右侧是选中队的名单；选中哪支队由 URL 表达，刷新与分享链接都落在同一支队上。

两处信息取舍是这个能力的核心。球队列显示人数与男/女构成而不是队伍平均 UTR——
一场比赛要 1 名女子打混双、2 名打女双，场上至少 3 名女队员是硬约束，而 26 人
名单的平均值跟真正上场的 8 个人关系不大。名单里评级类别为空的球员显示「待定」，
不显示任何具体类别：`Unrated` 属于第二类还是第三类取决于该队员有无 USTA 比赛
历史，总表不带这个信息，页面替它下结论就等于决定了谁占用「场上至多 2 名自评级」
的名额。

球队可以有一个人工维护的中文名，界面上以 code 为主、中文名为辅——code 是大家
实际在用的叫法，而多数联队没有自然的中文名。
## Requirements
### Requirement: 名单浏览页由 URL 表达赛季、组别与选中球队
前端 SHALL 在 `/[season]/[division]/teams` 提供球队列表，在
`/[season]/[division]/teams/[code]` 提供某支球队的名单。选中的球队
MUST 由 URL 表达，MUST NOT 只存在于客户端状态——URL 决定看的是哪支队，
客户端另存一份会与地址栏分歧，刷新与分享链接都会丢失选中项。

#### Scenario: 选中球队反映在地址栏
- **WHEN** 从球队列表中选择一支球队
- **THEN** 地址栏变为该球队的名单地址
- **AND** 直接访问该地址得到同一视图

#### Scenario: 未选球队时不自动跳转
- **WHEN** 访问 `/[season]/[division]/teams` 且未指定球队
- **THEN** 停留在该地址，不重定向到任何一支具体球队

#### Scenario: 切换赛季或组别保持在名单页
- **WHEN** 在名单页通过侧栏切换器切到另一个赛季组别
- **THEN** 进入该赛季组别的球队列表页

### Requirement: 未选球队时呈现空状态而非空名单
未选中球队时，内容区 MUST 呈现提示选择球队的空状态，MUST NOT 呈现一张
空的名单表格——空表格读作「这支队没有球员」，与「还没选队」是两个不同的断言。

#### Scenario: 空状态提示选择
- **WHEN** 访问球队列表页且未选中球队
- **THEN** 内容区显示提示从列表中选择一支球队的空状态
- **AND** 不渲染名单表格的表头或行

#### Scenario: 球队列表始终可见
- **WHEN** 处于空状态
- **THEN** 球队列表仍然渲染，可直接从中选择

### Requirement: 球队列表显示人数与性别构成
球队列表的每一行 SHALL 显示球队 code、名单总人数，以及男、女各自的人数。
性别为空的记录 MUST 单列一档计数，MUST NOT 并入男或女——并入会让某一侧
的人数凭空多出一个人。列表 SHALL 按 code 排序。

一场比赛需要 1 名女子打混双、2 名打女双，因此场上至少 3 名女队员是硬约束；
全队平均 UTR 不是。这决定了这个位置放的是性别构成而不是平均分。

#### Scenario: 每行的分项人数与总数一致
- **WHEN** 渲染球队列表
- **THEN** 每一行的男、女与性别未填三项之和等于该行的总人数

#### Scenario: 性别缺失单独成档
- **WHEN** 某支球队有名单记录的性别为空
- **THEN** 该记录计入独立的一档，不计入男，也不计入女

#### Scenario: 列表顺序稳定
- **WHEN** 反复渲染同一组别的球队列表
- **THEN** 球队顺序一致，按 code 排列

### Requirement: 名单表按参赛 UTR 降序展示球员
球队名单 SHALL 按参赛 UTR 从高到低展示，列出姓名、性别、参赛 UTR 与
UTR 来源。前端 MUST NOT 自行重新排序——后端已按该次序返回，两处各排一次
会在同值时给出不同结果。

#### Scenario: 强者在前
- **WHEN** 打开一支球队的名单
- **THEN** 记录按参赛 UTR 从高到低排列

#### Scenario: 前端不改变后端给出的次序
- **WHEN** 后端返回的名单中有参赛 UTR 相同的两条记录
- **THEN** 页面上的先后与后端返回的先后一致

#### Scenario: 名单页显示球队的人数与性别构成
- **WHEN** 打开一支球队的名单
- **THEN** 页首显示该队总人数与男、女人数

### Requirement: 取数失败与未找到只替换内容区
名单页取数失败或球队不存在时 MUST 只把内容区换成对应状态，侧栏与球队列
MUST 仍然渲染——从球队列换一支队正是这两种情况下的出路，而框架默认的
未找到页会替换整个窗口，把出路一并拿走。

#### Scenario: 后端不可达
- **WHEN** 名单页取数失败
- **THEN** 侧栏与球队列仍然渲染，只有内容区呈现错误态

#### Scenario: 未知球队
- **WHEN** 访问一个不存在的球队 code
- **THEN** 内容区呈现「没有这支球队」，侧栏与球队列仍在
- **AND** 不呈现一张空名单——空名单读作「这支队没有球员」，是另一句话

#### Scenario: 未知球队的响应状态
- **WHEN** 请求一个不存在的球队 code
- **THEN** HTTP 状态是 404

- **WHEN** 检查构建产物中浏览器会下载的部分
- **THEN** 其中不含后端共享密钥

### Requirement: UTR 来源给出判定类别与取值出处
名单的「UTR 来源」SHALL 呈现系统判定的评级类别；评级类别为空时 MUST 呈现为「待定」，
MUST NOT 呈现为自评、委员会审定或任何其他具体类别。

判定类别有三档：已认证 / 委员会审定 / 队长评定。Appeal 是独立标志，骑在类别之上而不
取代它——真实数据里 Rated、Projected、Unrated 三种都出现过 Appeal——因此 SHALL 以
`<类别> · Appeal` 呈现，MUST NOT 因为原文没了就把 Appeal 一起丢掉。

原状态文本（总表原文）**不再存在于数据来源里**，因此页面 MUST NOT 再渲染它，也
MUST NOT 用任何字段冒充它。之前呈现原文是因为 `Unrated` 属于第二类还是第三类取决于
该队员有无 USTA 比赛历史，总表不携带这项信息；这条判断上的克制照旧——页面仍然只在
类别确凿时给类别，不确凿就写「待定」。

当参赛 UTR 不是该赛季的冻结值而是按推导链取得的，该行 SHALL 在参赛 UTR 旁标注估算，
逐字为 `估算 · <年份> 参赛值` 或 `估算 · 当前已认证值`，用 warning 档。
MUST NOT 只写「估算」而不写年份——用 2025 的值估 2026 与用 2023 的值估 2026 是两种
可信度。

推导链一个值都取不到时（参赛 UTR 与来源同为 null），该行 SHALL 以 `无参赛 UTR` 代替
数字，用**中性**档：没有数字不等于数字可疑。MUST NOT 显示 0 或空白 —— 0 是一个合法
UTR，空白读起来像页面出错。

#### Scenario: 已认证记录
- **WHEN** 某条记录的评级类别为已认证
- **THEN** 显示「已认证」

#### Scenario: 委员会审定记录
- **WHEN** 某条记录的评级类别为委员会审定
- **THEN** 显示「委员会审定」

#### Scenario: 队长评定记录
- **WHEN** 某条记录的评级类别为队长评定
- **THEN** 显示「队长评定」

#### Scenario: 未判定记录显示待定
- **WHEN** 某条记录的评级类别为空
- **THEN** 显示「待定」
- **AND** 页面上不出现「自评」或任何具体类别的字样

#### Scenario: Appeal 不改变类别但仍然可见
- **WHEN** 某条记录处于 Appeal 状态
- **THEN** 类别照常显示，并在其后附 `· Appeal`

#### Scenario: 不再出现总表原文
- **WHEN** 渲染名单表的任一行
- **THEN** 页面上不出现 `Rated` / `Projected` / `Unrated` 等原始状态文本

#### Scenario: 推导值带年份标注
- **WHEN** 某名队员的参赛 UTR 取自更早赛季的值
- **THEN** 该行标注 `估算 · <该年份> 参赛值`

#### Scenario: 取自当前双打值的标注
- **WHEN** 某名队员的参赛 UTR 取自当前已认证的双打 UTR
- **THEN** 该行标注 `估算 · 当前已认证值`

#### Scenario: 一个值都取不到时代替数字
- **WHEN** 某名队员的参赛 UTR 与来源同为 null
- **THEN** 该行以 `无参赛 UTR` 代替数字，用中性档
- **AND** 不出现估算标注 —— 没有数字不等于数字可疑

#### Scenario: 冻结值不标注
- **WHEN** 某名队员该赛季有 match UTR
- **THEN** 该行不出现估算标注

### Requirement: 名单页显示当前 UTR 并说明它的维护方式
名单表 SHALL 显示每名队员的当前单打 UTR 与当前双打 UTR，各自带其状态
（`rated` / `projected` / `unrated`，未填时不显示状态）。值为空时 SHALL 显示 `—`。

页面 SHALL 在这两列附近逐字呈现 `当前 UTR 由人工维护，未与 UTR 官网同步`，用中性档。

这两列是推导链第二步的输入：没有它们，看的人无从判断某个估算为什么落在那里，也无从
在本赛季参赛 UTR 出来之前自己先估一个。而这些数字来自管理界面里的人工录入，不来自
UTR 官网同步——一个看起来像官方数据的数字若没有说明它多旧、由谁填，读的人会按官方
数据用它。当前它们**一个都没有**，因此这两列会是一整列 `—`；说明正是为这个空窗写的。

#### Scenario: 两列可见
- **WHEN** 打开任一球队的名单
- **THEN** 表中出现当前单打 UTR 与当前双打 UTR 两列

#### Scenario: 有值时带状态
- **WHEN** 某名队员的当前双打 UTR 有值且状态为 `rated`
- **THEN** 该单元格显示该值与其状态

#### Scenario: 空值显示破折号
- **WHEN** 某名队员的当前单打 UTR 为空
- **THEN** 该单元格显示 `—`

#### Scenario: 列为空时说明仍在
- **WHEN** 该队全部队员的当前 UTR 均为空
- **THEN** 说明仍然呈现
